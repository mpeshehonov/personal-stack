# Career Ops OS (locked decisions)

Цель: тревога не должна каждый раз заново решать «куда / что писать / какое резюме».
Решения ниже принимаются **один раз** (или раз в 4 недели по пятничным цифрам).

## Режим (заполни сам, не меняй каждый день)

| Режим | Денег | Разрешено | Запрещено |
|-------|-------|-----------|-----------|
| GREEN | 3+ мес | выбор, ниши, продукт | — |
| YELLOW | 1–3 мес | найм + фриланс + outbound | новый SaaS «с нуля» |
| RED | мало / ASAP | отклики, контакты, созвоны, текущие клиенты | полировка резюме, 30 ниш, рефактор агента, идеальная система |

**Сейчас: RED → контур A (найм) primary. Master резюме под Senior Frontend — freeze после sync площадок.**  
Контур B (клиенты) — только если есть слот после дневной нормы откликов.

## Master Profile = единственный источник правды

```
site/content/resume/resume.md          # RU master (HH / Habr / PDF)
site/content/resume/en/resume.md       # EN master (LinkedIn)
site/lib/resume-data.ts                # сайт /resume
agent/memory/career-copy-notes.md      # факты, нельзя выдумывать %
```

Площадки = копии master, не отдельные «правды».

### Правило синка площадок

- **Большой sync:** раз в месяц ИЛИ после оффера / нового места / сильного кейса.
- **Малый:** не делать. Правка одной строки на HH «потому что тревожно» = запрет.
- После sync: **freeze 14 дней** — откликаться текущей версией, не редактировать.

Тест «нейрослоп vs проф»: если фразу можно вставить любому Senior FE без твоих фактов — удалить.  
Разрешено: глагол + что + стек/контекст + результат (или масштаб: sole FE, 1 of 2, dozens of users).

**F-паттерн (беглое чтение):** ключевые слова в начале буллета и в первых строках «О себе».  
HR-ключевики: `CI/CD (GitHub Actions)`, не только `GitHub Actions`. Простой язык: `встраиваемый виджет`, не `embed-виджет`.

## Позиционирование на 4 недели (одна гипотеза)

**A (active):** Senior Frontend Engineer  
React / TypeScript / JavaScript / Next.js / сложные продуктовые UI / модуль от API до production.

**B / C (на полке):** Product Engineer dual-title, Fullstack-AI, Founding — не трогать, пока по A нет 40+ качественных откликов и цифр.

Не решать «кем быть навсегда». Решать пятничной воронкой.

## Недельный цикл

### Понедельник (30–45 мин) — план, не отклики

Зафиксировать нормы на неделю (RED):

- 15 качественных откликов (не 50 шаблонов)
- 5 прямых контактов (рекрутер / hiring manager / знакомый)
- 5 follow-up по старым
- 0 правок резюме (если не день большого sync)

### Вт–Чт (2–3 ч/день max)

На каждый день:

1. 3 отклика по чеклисту ниже  
2. 1–2 прямых контакта  
3. follow-up из трекера  
4. стоп

Агент: находит / фильтрует / готовит cover.  
Ты: APPROVE + отправка + интервью.

### Пятница (30 мин) — только цифры

```
найдено → отклики → ответы → скрининги → интервью → офферы
```

Менять стратегию только если: **≥40 откликов и 0 ответов** ИЛИ **≥10 скринингов и 0 дальше**.  
Иначе: ещё неделя того же процесса.

## Чеклист одного отклика (анти-хаос)

1. Fit ≥ 70% стека (React/TS/продукт). Skip: RN-only, pure middle, agency spam «от 2 лет».  
2. Версия резюме: всегда **A** (пока не сменил гипотезу на пятнице).  
3. Cover: 4–6 строк под JD **или** кнопка «Сопровод» в боте → правка 2 мин. Не пустой шаблон HH, если роль в топ-priority.  
4. Запись в трекер (статус `applied`, next_action_date +5 дней).  
5. Не открывать резюме «чуть подправить».

## Трекер (одно место)

Либо Notion/таблица, либо позже CRM в агенте. Минимум колонок:

`date | type(job/client) | company | role | source | fit | status | next_action | next_date | note`

Статусы: `new → applied → replied → screen → interview → offer / rejected / ghost`.

Бот уже даёт: карточки, Ок/Мимо, сопровод, обучение источников.  
Не дублировать это пятью таблицами.

## Роли: агент vs ты

| Агент | Ты |
|-------|-----|
| Скан, score, shortlist | Решение like / pass |
| Черновик cover | Отправка и тон |
| Напоминание follow-up | Созвоны, переговоры |
| Diff master → площадки (`/jobs sync`) | Ручной paste на HH/LI/Habr |

## RED-протокол (когда «денег нет / срочно»)

Сегодня и каждый день до смены режима:

1. Не открывать резюме на правку.  
2. 3 отклика + 1 прямой контакт.  
3. Follow-up по всему, что старше 5 дней без ответа.  
4. Если есть текущий фриланс/знакомый — сообщение «есть слот на …».  
5. Агенту: только research + cover + трекинг. Не «давай пересоберём систему».

## Первый запуск (один раз, ~3 часа)

1. Признать текущий `resume.md` **Base A** (или один вечер правок max, потом freeze).  
2. Sync: HH + Habr + LinkedIn с master.  
3. Завести трекер.  
4. Заполнить режим GREEN/YELLOW/RED честно.  
5. Понедельник: нормы. Дальше — цикл, не идеал.
